## 1. 系统与架构概览
本项目的运行时配置以 `.env` 文件为唯一持久化载体，通过 `src/config.py` 中的单例 `Config` 类加载并暴露类型安全的属性；`src/core/config_manager.py` 提供对 `.env` 的原子读写与版本控制；`src/core/config_registry.py` 集中声明所有配置项的元数据（分类、UI 控件、校验规则、帮助文档链接等），驱动 Web 设置页动态渲染；`api/v1/endpoints/system_config.py` + `src/services/system_config_service.py` 构成 REST API 层，提供读取、验证、更新、导入/导出、通道测试等能力。

整体分层：
- 存储层：`.env` 文件（dotenv 格式）
- I/O 层：`ConfigManager`（原子写入、乐观版本、Compose 敏感值转义）
- 解析与校验层：`setup_env()` + `Config` dataclass + 各类 `parse_*` / `normalize_*` 工具函数
- 元数据注册层：`config_registry.py`（字段定义、分类、默认值、示例、文档链接）
- 服务层：`SystemConfigService`（聚合读取、合并运行时环境变量、校验、更新、重载）
- API 层：FastAPI 路由（GET/PUT `/config`、`/config/schema`、`/config/import`、`/config/export`、通道测试等）

## 2. 关键文件与职责
- `src/core/config_manager.py`：`.env` 行级解析、`apply_updates` 原子 upsert、`get_config_version` 哈希+mtime 版本、Compose 敏感键转义/还原
- `src/core/config_registry.py`：`_FIELD_DEFINITIONS`、`_CATEGORY_DEFINITIONS`、`SCHEMA_VERSION`，以及 `build_schema_response` / `get_field_definition` 等构建 UI schema 的工具
- `src/config.py`：`setup_env()` 启动时加载 `.env`，`Config` dataclass 定义全部配置项，大量 `parse_env_*` / `normalize_*` 函数实现容错与回退
- `src/services/system_config_service.py`：`SystemConfigService` 聚合 ConfigManager、Registry、Config，实现 get_config、validate、update、import/env export、LLM/通知通道测试、首次运行 setup 状态等
- `api/v1/endpoints/system_config.py`：FastAPI 路由，统一异常映射与鉴权（导出/导入需 admin session 或 DSA_DESKTOP_MODE）
- `api/v1/schemas/system_config.py`：Pydantic 模型定义所有请求/响应结构
- `.env.example`：完整的环境变量模板，含注释说明与示例

## 3. 加载、分层与覆盖策略
- 启动阶段：`main.py` / `server.py` 在进程入口调用 `setup_env()`，优先从 `ENV_FILE` 环境变量或项目根 `.env` 加载；支持 `override=True` 用于热重载场景
- 运行时显示值合并：`SystemConfigService.get_config` 将“进程环境注入的值”（如 Docker env_file）与“.env 保存的值”合并，后者优先级更高，保证 Web 设置页既能展示外部注入的配置，又不会意外覆盖磁盘
- 敏感值处理：`CUSTOM_WEBHOOK_BODY_TEMPLATE` 等 Compose 敏感键在写入时进行 `$$...` 转义，读取时还原，避免 Docker Compose 提前插值
- 服务器端掩码：部分 key（如 `LLM_USAGE_HMAC_SECRET`、`LLM_HERMES_API_KEY` 等）在返回给前端时会被替换为 `mask_token`，客户端需通过 `raw_value_exists` 和 `is_masked` 判断

## 4. 写入与并发安全
- 原子写入：`ConfigManager._atomic_upsert` 先写 `.tmp` 再 `os.replace`，当挂载卷不支持 rename 时回退到原地重写，确保并发下不出现半写损坏
- 乐观锁：每次更新返回新的 `config_version`（mtime_ns:sha256），`update_system_config` 接口要求客户端传入当前 version，冲突时返回 409
- 敏感键保护：当提交值为 mask token 且原值已存在时，跳过该键更新，防止误清空密钥
- 线程安全：`ConfigManager` 内部使用 `threading.RLock` 保护并发读写

## 5. 配置元数据与 Web 设置
- 所有可编辑配置项必须在 `_FIELD_DEFINITIONS` 中注册，包含 `data_type`、`ui_control`、`validation`、`default_value`、`help_key`、`examples`、`docs`、`warning_codes` 等
- 分类体系：base、ai_model、data_source、notification、system、agent、backtest、uncategorized，每个分类有 display_order 控制分组顺序
- Web 设置页通过 `/config/schema` 获取 schema，按 category/display_order 排序渲染表单；`/config` 返回带 schema 的当前值，支持只读预览与草稿验证
- 首次运行 Setup 状态：`/config/setup/status` 汇总 LLM 主模型、Agent、股票列表、通知渠道、存储等是否就绪，指导用户下一步操作

## 6. 校验与回退机制
- 数值型配置使用 `parse_env_int` / `parse_env_float`，非法值记录 warning 并回退到默认值，支持 min/max 钳制
- 字符串枚举类配置（如 `AGENT_CONTEXT_COMPRESSION_PROFILE`、`TICKFLOW_KLINE_ADJUST`）提供 normalize 函数，非法值回退到预设默认
- LLM 温度等多来源兼容：优先 `LLM_TEMPERATURE`，其次 provider-specific 环境变量，最后硬编码默认 0.7
- 新闻窗口、Agent 压缩、LiteLLM 模型前缀等均有专门的归一化与推断逻辑，保证向后兼容

## 7. 运行时重载与依赖刷新
- 更新成功后可选择 `reload_now=True`，触发 `setup_env(override=True)` 重新加载 dotenv，并重置 fetcher manager 与 search service 等单例，使新配置立即生效
- Agent/Generation Backend 状态查询支持“未保存草稿预览”，在不持久化的情况下模拟校验与 smoke test

## 8. 约束与约定（基于代码行为）
- 所有可被 Web 设置的键必须出现在 `config_registry.py` 的 `_FIELD_DEFINITIONS` 中，否则不会出现在 schema 中
- 更新接口强制携带 `config_version`，版本不一致直接拒绝（409 Conflict）
- 敏感键（如 `*_API_KEY`、`*_SECRET`、`LLM_USAGE_HMAC_SECRET` 等）在服务端返回时被掩码，客户端不得假设能读到明文
- `.env` 文件路径可通过 `ENV_FILE` 环境变量覆盖，否则默认为项目根目录下的 `.env`
- Docker Compose 敏感键（目前仅 `CUSTOM_WEBHOOK_BODY_TEMPLATE`）写入时必须转义 `$...` 为 `$$...`，读取时还原

## 9. 相关 API 与入口
- `GET /api/v1/config`：获取当前配置（可选附带 schema）
- `PUT /api/v1/config`：批量更新配置（带版本冲突保护）
- `GET /api/v1/config/schema`：获取字段元数据（供前端渲染）
- `POST /api/v1/config/import`：导入 `.env` 文本（需鉴权）
- `GET /api/v1/config/export`：导出 `.env` 文本（需鉴权）
- `POST /api/v1/config/validate`：预校验（不持久化）
- `POST /api/v1/config/generation-backends/smoke-test`：生成后端连通性测试
- `POST /api/v1/config/notification/test-channel`：通知通道测试
- `GET /api/v1/config/setup/status`：首次运行就绪检查

该系统以 `.env` 为中心，结合强类型的 dataclass 配置、完备的元数据注册、原子写入与乐观锁，实现了可在 Web 界面可视化管理、热重载、安全回滚的运行期配置体系。
